# v1.1.10 发布暴露面复核

## 1. 总览

2026-11-13，对实际电脑版 Vite 产物 `apps/app-shell/dist` 执行只读 Web 扫描，并复核 Electron 与发布配置。项目仅维护 Windows 电脑版和 PHP 网页版。

扫描覆盖 16 个文件、13 个 JS 产物、0 个原生二进制，发现为 0；工具评分 100/A 仅表示这些启发式规则未命中，不能证明没有漏洞、难以逆向或已经验证安装包。Electron fuse 运行状态和旧版到新版实际安装不属于本次 Web 扫描覆盖范围。

## 3. 逐项证据与修复

- 主窗口和微博登录窗口均保留 `contextIsolation:true`、`nodeIntegration:false`、`sandbox:true`；导航和新窗口处理继续使用原有边界，未为打包关闭隔离。
- 发布仅使用 Windows job；`--publish never` 关闭打包器隐式上传，构建成功后由工作流创建草稿、上传校验文件再公开发布。
- NSIS 和 portable 均使用固定英文文件名；清单生成拒绝可能被 GitHub 改写的资产名，避免下载链接与附件不一致。
- Git 跟踪文件检查通过：没有生成安装包、依赖目录、本机配置或已知私钥/GitHub token 模式命中；此检查并不覆盖所有秘密类型。
- SIGN-WIN / UPDATE-AUTH 仍需受保护的正式代码签名配置才能完成身份认证增强。本次不生成替代证书，也不把 hash 描述为签名。

复跑命令：`py -3.14 -I <技能目录>/scripts/exposure_scan.py apps/app-shell/dist --profile web --json`。

## 4. 客户端无法解决的问题

本项目没有付费授权的客户端最终判定，解析算法本身随开源客户端分发。微博登录态与手工 Cookie 仍需按本机会话保护，不应写入发布包或作为服务端长期秘密。前端混淆不能代替服务端 API Key 校验、发布权限保护、正式签名或真实升级验收。

## 5. 修复顺序

- P0：本次扫描没有确认的硬编码密钥命中；发现真实泄漏时先撤销凭据，再移除产物内容。
- P1：后续配置正式 Windows 签名；发布后核验公开安装包与更新清单，真实旧版升级安装单独验收。
- P2：兼容性验证后再评估 Electron fuse / ASAR 完整性增强；当前不声称已完成原生硬化。
