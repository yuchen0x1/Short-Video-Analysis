# v1.1.9 发布暴露面复核

> 范围更正：当前仅维护 Windows 电脑版和 PHP 网页版，独立移动端已移除。下文为更正前的历史工作快照，相关移动端记录不代表当前功能；见 [产品范围](../PRODUCT_SCOPE.md)。

## 1. 总览

2026-11-13，按 `reverse-engineering-exposure-audit` 技能，对本项目两端实际 Vite 构建目录执行只读扫描，并复核 Electron 配置和发布流程。项目本身为 AGPL 开源软件，客户端源码可读是既定属性，不以混淆作为安全承诺。

两份 Web 扫描各覆盖 16 文件 / 13 JS 文件，启发式发现均为 0，工具评分均为 100/A。该分数仅描述扫描规则命中，不能证明客户端难以逆向、没有漏洞或已验证安装包安全。原生二进制、APK、Electron fuse 的运行状态不在这两次 Web 扫描范围内。

## 3. 逐项证据与修复

- 两个 `BrowserWindow` 配置均为 `contextIsolation:true`、`nodeIntegration:false`、`sandbox:true`。保留现有受限 preload 与网络边界，不在发版时为方便打包关闭隔离。参考 [Electron 安全建议](https://www.electronjs.org/docs/latest/tutorial/security/)。
- 旧发布运行 [43136701327](https://github.com/yuchen0x1/Short-Video-Analysis/actions/runs/43136701327) 在 `Build Windows installers` 失败：固定 `electronDist=node_modules/electron/dist` 在 runner 上不存在。本次移除固定本机路径，使用打包器获取匹配 runtime 的标准流程。
- `dist:win` 显式传 `--publish never`，安装包构建与 GitHub 上传分离。发布说明从版本化文档生成；草稿失败可重试，已发布版本拒绝覆盖。行为依据 [electron-builder v26 发布文档](https://www.electron.build/v26/docs/publish/)。
- SIGN-WIN 与 UPDATE-AUTH：需要项目维护者提供受保护的正式代码签名配置后才能完成认证增强；本次不会创建伪证书、提交私钥或把 SHA 校验描述为签名。
- Android 仅在既有 `ANDROID_RELEASE_ENABLED` 和正式签名配置可用时发布；本次不改变密钥/签名身份，不上传测试签名或 debug 包。

复跑扫描：

```powershell
py -3.14 -I <技能目录>/scripts/exposure_scan.py apps/app-shell/dist --profile web --json
py -3.14 -I <技能目录>/scripts/exposure_scan.py apps/mobile/dist --profile web --json
```

## 4. 客户端无法解决的问题

本项目没有付费授权判定。本地解析器、公开平台地址和接口规则会随客户端提供，不能作为秘密。用户手工输入或宿主登录态提供的微博凭据，仍需按设备会话保护；本次备份显式排除凭据，且 PHP/JS 微博结果不跨账号使用缓存。静态扫描不等于对用户真实浏览器存储进行审计。

代码签名、GitHub 账户/发布权限保护和真实旧版到新版安装验收不能由前端混淆替代。
